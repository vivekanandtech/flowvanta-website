Step 1 — Create Your Railway Project

1

New project → Deploy from Docker image

Log in to railway.app → click New Project → select Deploy from Docker image. In the image field, enter n8nio/n8n. Railway will pull the latest stable n8n image. Do not click Deploy yet.

Step 2 — Add PostgreSQL

2

Add a database service to your project

In your Railway project, click + New Service → Database → PostgreSQL. Railway provisions a Postgres instance in about 30 seconds. Click on the Postgres service → Variables tab → copy the DATABASE_URL value. You'll need it in Step 3.

Do not skip the database

Without PostgreSQL, n8n uses SQLite stored in the container filesystem. Railway containers do not have persistent storage by default — every redeploy wipes your workflows, credentials, and execution history. PostgreSQL is non-negotiable for production.

Step 3 — Configure Environment Variables

Click on your n8n service → Variables tab → add each of these:

# Database
DB_TYPE=postgresdb
DB_POSTGRESDB_HOST=${{ '{' }}Postgres.PGHOST}}
DB_POSTGRESDB_PORT=${{ '{' }}Postgres.PGPORT}}
DB_POSTGRESDB_DATABASE=${{ '{' }}Postgres.PGDATABASE}}
DB_POSTGRESDB_USER=${{ '{' }}Postgres.PGUSER}}
DB_POSTGRESDB_PASSWORD=${{ '{' }}Postgres.PGPASSWORD}}

# n8n core settings
N8N_HOST=your-subdomain.railway.app
N8N_PORT=5678
N8N_PROTOCOL=https
WEBHOOK_URL=https://your-subdomain.railway.app/

# Security
N8N_BASIC_AUTH_ACTIVE=true
N8N_BASIC_AUTH_USER=admin
N8N_BASIC_AUTH_PASSWORD=change-this-to-something-strong

# Encryption key (generate once, never change)
N8N_ENCRYPTION_KEY=generate-a-32-char-random-string

# Timezone
GENERIC_TIMEZONE=Asia/Kolkata

# Performance
EXECUTIONS_DATA_MAX_AGE=336
EXECUTIONS_DATA_PRUNE=true
Pro tip: Railway variable references

Use Railway's reference syntax ${{'{'}Postgres.PGHOST}} instead of hardcoding database values. If Railway rotates your credentials, your n8n instance updates automatically without any manual changes.

Generate a secure encryption key

The N8N_ENCRYPTION_KEY is used to encrypt all your credentials in the database. Generate it once and never change it — changing it invalidates all stored credentials. Use this command to generate a secure key:

# macOS/Linux — run in terminal
openssl rand -hex 16

# Output example:
a3f8c2d1e5b7940261f4e8d3c9a72b05

Step 4 — Set the Port and Deploy

4

Set PORT variable and deploy

Add one final variable: PORT=5678. Railway uses the PORT environment variable to know which port to expose. Without it, Railway's automatic port detection may not find n8n's port. Now click Deploy.

Your first deploy takes 2–3 minutes as Railway pulls the Docker image and initialises the database schema. Watch the build logs — a successful start ends with:

Editor is now accessible via:
http://localhost:5678/

Press "o" to open in Browser

Step 5 — Add a Custom Domain

5

Generate Railway domain or add your own

In your n8n service → Settings tab → Networking → click Generate Domain for a free *.railway.app URL. To use your own domain (e.g. n8n.flowvanta.dev), click Add Custom Domain and follow the CNAME instructions.

After adding your custom domain, update the environment variables:

N8N_HOST=n8n.yourdomain.com
WEBHOOK_URL=https://n8n.yourdomain.com/

The WEBHOOK_URL is critical. This is the base URL that n8n uses when generating webhook URLs for your automations. If it's wrong, webhook triggers will point to the wrong address and never fire.

Step 6 — Configure SMTP for Email Nodes

n8n's Gmail and Email nodes require SMTP credentials for sending. Add these variables to enable email-sending capabilities:

# Gmail SMTP (requires App Password, not your account password)
N8N_EMAIL_MODE=smtp
N8N_SMTP_HOST=smtp.gmail.com
N8N_SMTP_PORT=465
N8N_SMTP_SSL=true
N8N_SMTP_USER=your@gmail.com
N8N_SMTP_PASS=your-gmail-app-password
N8N_SMTP_SENDER=your@gmail.com
Gmail App Passwords

To get a Gmail App Password: Google Account → Security → 2-Step Verification → App passwords → create one for "n8n". Use this 16-character password, not your Gmail login password.

Production Hardening

Enable worker mode for heavy workflows

If you run CPU-intensive workflows (large data transforms, many parallel executions), add EXECUTIONS_PROCESS=own to isolate executions in separate processes. This prevents a single slow workflow from blocking others.

Set execution limits

# Prevent runaway workflows
N8N_DEFAULT_BINARY_DATA_MODE=filesystem
EXECUTIONS_DATA_MAX_AGE=336       # 2 weeks retention
EXECUTIONS_DATA_PRUNE=true        # Auto-clean old executions
N8N_PAYLOAD_SIZE_MAX=16           # 16MB max payload

Set up monitoring

Railway has a built-in Metrics tab showing CPU, memory, and network. For production n8n monitoring, also set up the n8n Error Trigger node in a dedicated monitoring workflow — route failures to Slack or email so you know when automations break.

Regular backups

Railway's PostgreSQL plans include automated backups. For extra safety, create an n8n workflow that runs nightly to export your workflow JSON files to Google Drive using n8n's built-in export API endpoint: GET /api/v1/workflows.

Cost Optimisation

Railway bills by usage (compute + memory). A typical n8n instance for a small business uses:

  • Compute — 0.5–1 vCPU most of the time, spikes during executions
  • Memory — 256–512MB base, 1–2GB during heavy workflows
  • Storage — PostgreSQL grows slowly, expect 100–500MB for first year

Expected Railway bill: $5–12/month for a typical automation workload with 1,000–10,000 executions/month. Add $5–7 for the PostgreSQL instance. Total: $10–19/month versus $20+ for n8n Cloud — with no execution limits.

Troubleshooting — common issues

Webhooks not triggering: Check WEBHOOK_URL matches your actual domain exactly, including the trailing slash.

Credentials lost after redeploy: You skipped the PostgreSQL setup. Add it now and run n8n's data migration.

502 errors on startup: n8n takes 20–30 seconds to start. Railway's health check may fire too early. Add a startup delay in Railway service settings.
