Build an AI Customer Support System: Step-by-Step with n8n + GPT-4o

Flowvanta Engineering
June 2026 12 min read

A FinTech client came to us with 500+ support emails arriving daily. Three agents were spending their entire shift just triaging — deciding which emails were urgent, which were complaints, which were sales opportunities. They hadn't even started replying yet.

We built an n8n + GPT-4o pipeline that handles all of it automatically. Every email is classified, a reply is drafted, and the ticket is logged in their helpdesk — before their agents even open their laptops. This is how we built it.

How the System Works

The pipeline has four stages: Ingest → Classify → Draft → Deliver. Each stage is a set of n8n nodes that runs in sequence. The entire pipeline executes in under 4 seconds per email.

  • Ingest — Gmail trigger fires on every new unread email in the support inbox
  • Classify — GPT-4o reads the email and returns a structured JSON object: category, urgency, sentiment, intent
  • Draft — GPT-4o generates a personalised reply using your knowledge base and response templates
  • Deliver — Draft is saved to Gmail as a draft (human reviews), logged to your helpdesk, and urgent cases trigger a Slack alert
Important: Human-in-the-loop

This system saves drafts — it does not auto-send. A human reviews and sends each reply. This keeps quality high while eliminating all the manual classification and drafting work. You can automate the send step once you trust the system, typically after 2–4 weeks of monitoring.

Building the Pipeline

1

Gmail Trigger — catch every new email

Add a Gmail Trigger node. Set it to poll every 1 minute (or use Push if you have Google Workspace). Filter to only unread emails in your support label/inbox. Connect your Gmail account via OAuth.

// Gmail Trigger settings
Trigger on: New Email
Label: INBOX (or your support label ID)
Only unread: true
Poll interval: 1 minute
2

Extract and clean the email content

Add a Code node. Strip HTML tags from the email body, extract the sender name/domain, and build a clean text payload for the AI. This prevents the AI from wasting tokens on HTML formatting.

// Code node — clean email
const body = $input.first().json;

// Strip HTML
const cleanText = body.text ||
  body.html.replace(/<[^>]*>/g, '').trim();

// Extract sender info
const senderEmail = body.from.value[0].address;
const senderName  = body.from.value[0].name;
const senderDomain = senderEmail.split('@')[1];

return [{
  json: {
    subject: body.subject,
    body: cleanText.slice(0, 2000), // cap at 2k tokens
    senderEmail,
    senderName,
    senderDomain,
    messageId: body.messageId,
    threadId: body.threadId,
  }
}];
3

GPT-4o Classification

Add an OpenAI node set to "Chat Completion." This is the core of the system. The prompt asks GPT-4o to return a structured JSON object with everything your team needs to triage the email.

// System prompt
You are an expert support triage AI for a FinTech company.
Analyse the customer email and return ONLY valid JSON — no markdown.

Categories: billing | technical | account | complaint |
            sales-inquiry | spam | other

Urgency levels: critical | high | medium | low

Return format:
{
  "category": "billing",
  "urgency": "high",
  "sentiment": "frustrated",
  "intent": "payment failed and wants refund",
  "summary": "1-sentence summary",
  "requiresHuman": true,
  "suggestedTeam": "billing-team"
}

// User prompt
From: {{ $json.senderName }} <{{ $json.senderEmail }}>
Subject: {{ $json.subject }}
Message: {{ $json.body }}
4

Parse the classification response

Add another Code node to parse the GPT-4o JSON response. Handle potential JSON parsing errors gracefully — if the AI returns malformed JSON, default to a "needs-human-review" classification rather than crashing the workflow.

// Parse AI classification
const aiResponse = $input.first().json.message.content;

let classification;
try {
  classification = JSON.parse(aiResponse);
} catch(e) {
  // Fallback if JSON parsing fails
  classification = {
    category: 'other',
    urgency: 'medium',
    sentiment: 'neutral',
    requiresHuman: true,
    summary: 'AI parsing failed — manual review needed'
  };
}

return [{ json: {
  ...classification,
  ...$input.first().json
}}];
5

GPT-4o Draft Reply Generation

Add a second OpenAI node to generate the reply. This is where your knowledge base matters. Include your FAQ, product documentation snippets, and response tone guidelines in the system prompt. The better your knowledge base, the better the drafts.

// System prompt for drafting
You are a customer support agent for [Company Name].
Write a professional, empathetic reply to the customer email below.

Tone guidelines:
- Acknowledge the customer's concern first
- Be concise — 3-5 sentences max
- Never promise specific timelines you can't control
- Sign off as "The [Company] Support Team"

Knowledge base snippets:
[Paste your FAQ answers, pricing info, refund policy here]

Do not include a subject line. Write only the email body.

// User prompt
Customer category: {{ $json.category }}
Customer sentiment: {{ $json.sentiment }}
Intent: {{ $json.intent }}

Original email:
From: {{ $json.senderName }}
{{ $json.body }}
6

IF node — route by urgency

Branch your workflow. Critical and High urgency emails trigger an immediate Slack alert to your on-call agent. All emails proceed to Gmail draft creation and helpdesk logging regardless of urgency.

7

Save as Gmail Draft + Label the original

Add a Gmail node set to "Create Draft." Use the threadId from Step 2 to ensure the draft appears as a reply in the correct thread. Add another Gmail node to apply labels — "AI-Triaged" and the category label.

// Gmail — Create Draft node
To: {{ $json.senderEmail }}
Subject: Re: {{ $json.subject }}
Body: {{ $json.message.content }}
Thread ID: {{ $json.threadId }}
In-Reply-To: {{ $json.messageId }}
8

Log to helpdesk and notify on Slack

Add an HTTP Request node to create a ticket in your helpdesk (Zendesk, Freshdesk, Intercom — all have REST APIs). Set the ticket title, description, priority (mapped from your urgency field), and assignee team.

Monitoring and Quality Control

Build a review dashboard

Add a Google Sheets node at the end of your workflow to log every processed email: timestamp, sender, category, urgency, sentiment, and whether the draft was used. Review this sheet weekly for the first month. You'll spot patterns that help you improve your knowledge base and prompts.

Track draft acceptance rate

The most important metric is how often your agents use the AI draft versus rewrite it. Aim for 70%+ acceptance rate. If a category consistently gets rewritten, improve the system prompt for that category specifically.

Add feedback to the knowledge base

When an agent rewrites a draft, capture the rewritten version and add it as a few-shot example in your system prompt for that category. This creates a flywheel — the system gets better every week based on real agent corrections.

Cost breakdown for 500 emails/day

At GPT-4o pricing: ~$0.01 per classification + $0.02 per draft = $0.03/email. 500 emails/day = $15/day = ~$450/month. Compare that to the $8,000–15,000/month cost of 3 support agents doing the same work manually.

Common Failure Modes and Fixes

Emails in foreign languages

GPT-4o handles multilingual input natively. Add a language detection step and include the detected language in your drafting prompt: "Reply in {{ $json.language }}." The model will match the customer's language automatically.

Attachments and images

For emails with attachments (screenshots, receipts), add a step to extract attachment metadata and include filenames in the context passed to GPT-4o. If you need actual image analysis, use GPT-4o Vision by passing the base64-encoded image in the user message.

Gmail API rate limits

Gmail's API allows 250 quota units per user per second. With 500 emails/day running every minute, you'll rarely hit this. If you do, add a Wait node between API calls and enable n8n's built-in rate limiting on the Gmail nodes.
